# Screen 4 Rose Words Hover — Design Spec

**Дата:** 2026-06-22  
**Экран:** `Screen4_Rose`  
**Цель:** Сделать падающие слова заметно чаще и добавить "магическую" hover-анимацию без изменения навигации и общей атмосферы сцены.

---

## 1. Изменение поведения

### Частота появления слов
- Текущий интервал появления слов (`1200ms`) уменьшается примерно до `550–750ms`.
- Экран должен выглядеть более живым, но не перегруженным.
- Количество одновременно хранимых слов остаётся ограниченным, чтобы не раздувать DOM и не просаживать плавность.

### Hover-поведение
- Падающие слова должны стать интерактивными для курсора.
- При наведении слово:
  - слегка увеличивается;
  - становится визуально ярче;
  - получает мягкое розовое свечение;
  - показывает небольшой "магический" след или ореол.
- Эффект должен оставаться романтичным и лёгким, без агрессивных вспышек или тряски.

---

## 2. Подход реализации

### Рекомендованный путь
- Сохранить основное падение слов через `framer-motion`.
- Убрать блокировку наведения (`pointer-events-none`) у самих слов.
- Добавить hover-анимацию прямо в `motion.span` через `whileHover`.
- Для "магического" следа использовать сочетание:
  - усиленного `text-shadow`;
  - `filter: drop-shadow(...)`;
  - дополнительного полупрозрачного слоя через CSS-класс.

### Почему так
- Изменение остаётся локальным внутри `Screen4_Rose` и `rose.module.scss`.
- Не затрагивается `useScreenStore`, навигация между экранами и остальная анимация розы.
- `framer-motion` уже используется на экране, поэтому hover-эффект будет согласован с текущим рендерингом.

## 3. Границы изменения

### Меняем
- `src/screens/Screen4_Rose.tsx`
- `src/styles/rose.module.scss`

### Не меняем
- Последовательность экранов `0..6`
- Контент массива `WORDS`
- Поведение `NavigationArrow`
- Остальные экраны и глобальную навигацию

---

## 4. Проверка

- Визуально убедиться, что слова появляются чаще, чем раньше.
- Проверить, что hover срабатывает на отдельных словах и не ломает падение.
- Убедиться, что экран остаётся отзывчивым и не выглядит перегруженным.
- Запустить `npm run lint`.

Если в проекте уже есть подходящие тесты для этой области, дополнительно запустить `npx vitest run`.

---

## 5. Ограничения и риски

- Слишком частое создание слов может перегрузить сцену, поэтому нужно сохранить разумный лимит массива.
- Hover не должен мешать кликам по другим важным элементам экрана.
- Эффект свечения не должен ухудшать читаемость текста на тёмном фоне.
